## ✨ 特性

- **托盘三态图标,一眼可辨**

  | 图标 | 状态 | 含义 |
  |:---:|---|---|
  | 🟢 绿 | 防待机 | 系统不睡,屏幕允许自动关 |
  | 🔵 蓝 | 防待机 + 屏幕常亮 | 系统不睡,屏幕也不关 |
  | ⚪ 灰 | 关闭 | 恢复系统默认行为 |

- **左键单击托盘图标 = 开 / 关切换**,不用进任何菜单;鼠标悬停显示已保持时长
- **右键菜单**:`防待机开启` / `屏幕常亮` / `资源管理器单窗口合并` / `键映射▸`(二级子菜单,内含 `F2→Ctrl+W`、`Win(左)→Ctrl(左)`,各自独立开关) / `开机自启` / `更多工具▸去除快捷方式小箭头` / `退出`,顶部另有一行置灰的实时状态项(同步显示当前状态与已保持时长);勾选「屏幕常亮」会自动连防待机一起开
- **资源管理器单窗口合并**(Win11,默认开启):新开的资源管理器窗口自动变成已有窗口里的新标签页——全 Windows 始终只有一扇资源管理器(详见下文专节)
- **全局键映射**(默认开启,两条独立开关,详见下文专节):低级键盘钩子实现——`F2→Ctrl+W` 浏览器/编辑器一键关标签、`左Win→左Ctrl` 开始菜单键改充 Ctrl,取代 PowerToys Keyboard Manager 里在用的映射——为此装整套 PowerToys 的可以卸了
- **去除快捷方式小箭头**(默认关,折叠在 `更多工具 ▸` 子菜单,详见下文专节):一键去除/恢复快捷方式左下角小箭头,可逆、还原系统默认;切换瞬间需管理员确认一次(UAC)
- **单实例**:Mutex 保证,重复启动静默退出,不会多开图标
- **零残留**:唤醒请求只挂在本进程,正常退出、被杀、注销、重启,系统都会自动撤销请求;防待机开启期间会临时把系统「在此时间后休眠」设为从不(见工作原理),关闭/退出即恢复,异常退出下次启动自愈
- **免安装单文件 exe**:数十 KB,无运行时依赖(依赖系统自带的 .NET Framework 运行)

## 📥 下载使用

1. 打开 [Releases](https://github.com/hss-ai/keep-awake/releases) 页,下载最新版的 **`KeepAwake.exe`** —— 单文件、免安装;**若 Releases 页暂无版本(二进制尚未发布),直接用下一节「从源码构建」,一条命令即可得到同样的 exe**;
2. 双击运行,托盘出现绿杯图标并弹气泡,防待机立即生效;
3. 左键托盘图标 = 开 / 关;右键菜单 = 屏幕常亮 / 退出。

> **遇到 SmartScreen 提示?** exe 未做代码签名,首次运行可能弹出「Windows 已保护你的电脑」——点 **「更多信息」→「仍要运行」** 即可,后续不再提示。
>
> Win11 默认把新托盘图标收进任务栏右下角 `^` 溢出区,拖到任务栏上即可常驻。

## 🛠 从源码构建

```console
python build_keep_awake.py
```

一条命令完成:**生成图标 → csc 编译 → 安装到 `%USERPROFILE%\Scripts\KeepAwake.exe` → 桌面创建「防待机」快捷方式**。重复执行 = 重建覆盖(会自动停掉在跑的旧实例)。

> **卸载**:退出托盘程序,删除 `%USERPROFILE%\Scripts\KeepAwake.exe` 与桌面「防待机」快捷方式即可,无其他残留。

构建环境:

| 依赖 | 说明 |
|---|---|
| Windows 10/11 | 编译器用系统自带的 `csc.exe`(.NET Framework 4.x),**无需安装 .NET SDK / Visual Studio / MSBuild** |
| Python 3.8+ + Pillow | 仅构建期用于生成图标(`pip install pillow`) |

> 装机的停旧实例/建快捷方式用系统自带 `taskkill` 与 `powershell.exe`,无额外依赖。

## 💻 命令行版用法

`keep_awake.py` 是零依赖的命令行版本(纯 Python 标准库),适合挂机下载、跑长任务、写进脚本:

```console
python keep_awake.py                # 阻止系统待机/休眠(屏幕允许自动关),Ctrl+C 退出
python keep_awake.py --display      # 连屏幕一起保持常亮
python keep_awake.py --minutes 90   # 90 分钟后自动结束并恢复默认
python keep_awake.py --quiet        # 不打印心跳行
```

| 参数 | 说明 |
|---|---|
| `--display` | 同时保持屏幕常亮(默认只阻止待机,屏幕可自动关闭) |
| `--minutes N` | `N` 分钟后自动结束并恢复默认;`0` = 不限时,Ctrl+C 退出 |
| `--quiet` | 不打印心跳行(默认每 0.5 秒刷新显示已保持 / 剩余时长) |

> ⚠️ **长时间插电挂机请用托盘版**:Win11 新型待机的「睡眠后休眠 - 固定超时」计时器会穿透 `SetThreadExecutionState`(系统进睡眠后约 30 分钟被强制休眠),命令行版没有电源护栏;托盘版开启防待机时会临时清零该计时器,关闭/退出即恢复。

## 🗂 资源管理器单窗口合并

第二个托盘功能(默认开启,右键菜单 `资源管理器单窗口合并` 随时关)。参照 ExplorerTabUtility 的思路,让全 Windows 只保留 **1 个资源管理器窗口**:之后新开的窗口——双击文件夹、Win+E、其他程序唤起——都会自动并进这扇窗口,变成一个新标签页。

工作方式:

- 监听**新建**的资源管理器窗口(`SetWinEventHook` + `EVENT_OBJECT_CREATE`,还原最小化不会误触发);
- **目标路径已在既有窗口的某条标签里时(哪怕藏在别的标签后面),直接激活那条标签**,不再开出一条内容重复的新标签——从其他程序「在资源管理器打开」此类目录(如终端/IDE 里 Reveal in Explorer)即自动切过去;定位方式:Shell 枚举同窗口标签的序号与标签栏 `TabListView` 子项序号一一对应(实测同构,标签项的 UIA Name 是本地化显示名无法按路径匹配),UIA `Select` 激活后以窗口标题核实;此路 UIA 失败时退回下方「新开标签」路径,行为不劣化(v1.4.2);
- 经 Shell COM 读取新窗口的路径,在既有窗口里经 UIA 调用标签栏「新建标签」按钮开出真新标签,再原地 `Navigate2` 到目标路径——零按键,不受中文输入法与前台焦点影响,然后关掉多余的新窗口;合并目标会排除仍在排队的新窗口(防「A 并进 B、B 又被关掉」的连环误并)与其它虚拟桌面上被 DWM 隐藏的窗口;此路不通时自动退回键盘注入兜底(`Ctrl+T` + 地址栏输入,含输入法隔离与剪贴板粘贴两级后备,打字/回车前复查前台,丢了就放弃合并);
- 第一个资源管理器窗口保留不合并——它就是「那一个」;
- 从其他程序「打开所在文件夹」(带文件选中)合并后定位到所在文件夹,但文件高亮不保留;
- 虚拟位置(回收站/此电脑等)`LocationURL` 为空,经 Shell 命名空间读 `::{GUID}` 路径照常导航(COM 正常时);COM 间歇无响应时**保留原窗口不合并**(宁可不并也不把位置丢成一刀切主页),代价是目标窗口可能多一个空白标签,手动关掉即可;
- 把标签拖出成独立窗口会被视为新窗口再并回——「全程只有一扇窗」正是本功能的目标;需要临时多窗口时,右键菜单关掉合并开关即可;
- 仅键盘兜底触发时才有约半秒按键注入;依赖 Win11 22H2+ 的资源管理器原生标签页,Win10 无此能力(开关无效,但不报错);
- ⚠️ 合并主路径依赖资源管理器标签栏的 UIA `AutomationId="AddButton"`(实测本机 Win11 的 `Navigate2` 新标签标志无效,只能这么绕);微软改版资源管理器可能使其失效——失效时自动退回键盘兜底,合并行为异常可看 `%TEMP%\KeepAwake_merge.log` 诊断日志。

真机测试脚本在 [`tests/`](tests/):`test_merge.py`(窗口计数判据)+ `probe_merge_once.py`(窗口标题=临时文件夹名判据,证明合并真实发生)+ `probe_reuse_tab.py`(目录已在既有标签时:激活该标签、不开重复标签、活动标签切换到位;覆盖「带文件选中/直接打开目录」两种外部唤起形态)。

## ⌨️ 全局键映射(F2→Ctrl+W、左Win→左Ctrl)

第三个托盘功能(默认开启,右键菜单 `键映射 ▸` 子菜单里两条映射各自随时关)。按 F2 等于按 Ctrl+W——浏览器/编辑器里一键关标签页;按左 Win 等于按左 Ctrl——键盘上易误触开始菜单的 Win 键改充 Ctrl 用,不再需要为这几条映射常驻整套 PowerToys。

工作方式:`WH_KEYBOARD_LL` 低级键盘钩子拦在全系统键盘流最前面(装在独立线程,不影响 UI、不拖慢按键),原键按下时吞掉并注入目标键,松开时补齐抬起。语义细节:

- **一次按压 = 一次输出**:按住原键的系统自动重复被吞掉不重发,长按 F2 不会连环关标签、长按 Win 也不会重复注入 Ctrl;
- **不碰你自己的 Ctrl**:按下原键那刻若你自己正按着 Ctrl(任一侧),只做该做的、不重复补按,松开原键也不替你抬 Ctrl;两条映射共享同一份 Ctrl 状态,先按住 F2 再按 Win(或反过来)也不会重复注入;
- **其它修饰键保留**:Shift+F2 = Shift+Ctrl+W、Alt+F2 = Alt+Ctrl+W,与物理按键模型一致(注意 Chrome 里 Shift+Ctrl+W 是关闭整个窗口);
- **左 Win 的本义全局被替换**:开始菜单、Win+D/E/L 等系统快捷键在**左 Win** 上失效——要开开始菜单用**右 Win**(不受影响)或菜单里关掉本映射;
- **无粘键**:keyup 只在对应 keydown 被吞时才吞(开关状态在按住期间翻转也不会让键卡在按下态),按住期间关映射/退出程序,欠下的抬起都会补还;
- **无自反馈**:本工具自己注入的键带内部魔数标记,钩子直接放行,不存在循环;
- **未提权的固有限制**(与 PowerToys 不提权时相同):UAC 安全桌面、管理员窗口里的原键不被映射;
- 开关即时生效;映射状态不持久化,每次启动默认开。

端到端测试:`tests/probe_keymap.py`(前台探针窗口实录收到的按键序列:注入 F2 / 左 Win 后断言只见目标键序列且原键被吞、自动重复只触发一次、他人按着 Ctrl 时不重复补按;场景覆盖两条映射)。

## 🧹 去除快捷方式小箭头

第四个托盘功能(**默认关,不常用,折叠在右键菜单 `更多工具 ▸` 子菜单**)。勾选即去除桌面与资源管理器中快捷方式左下角的小箭头,取消勾选恢复系统默认。

工作方式:

- 注册表 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\Shell Icons` 的字符串值 `29`(小箭头是 shell 图标索引 29)指向一张全透明图标——箭头照常渲染但内容为空。这是 Winaero 等工具的标准做法;**不动 `lnkfile\IsShortcut`**(那个做法会连带弄坏「固定到任务栏/开始屏幕」等功能)。
- 全透明图标不依赖系统 DLL 里"恰好透明"的图标序号(教程里的 `imageres.dll,197` 之类随系统版本漂移,选错会渲染成黑方块),而是运行时字节级手写生成到 `%LOCALAPPDATA%\KeepAwake\blank.ico`。**⚠实测暗坑(Win11 26300)**:32bpp ICO 的 alpha 若全 0,GDI 会判「这图没有 alpha 通道」按 RGB 渲染成**不透明黑方块**——AND 掩码全 1 也救不了(这条渲染路径不读掩码),PIL 默认写的 ICO 同样中招;正解是让一个像素 alpha=1、其余全 0(探针变体实验验证:仅此构造渲染为全透明)。
- **HKCU 同名键无效**:Win11 26300 实测(SHGetFileInfo 像素级判据,见 `tests/probe_arrow.py`)HKCU 的 `Shell Icons\29` 完全不被 shell 认账——网上教程两种写法都有,只有 HKLM 这条路是通的。
- 写 HKLM 需要管理员:勾选时工具弹一次 UAC(自我提权拉起一次性 `--arrow on/off` 实例,写完注册表+刷新图标即退),**常驻进程与其余全部功能照旧免管理员**。
- 可逆:若发现 `29` 原本已被其它工具写过,原值先备份到 HKCU,取消勾选时原样归还,不清掉别人的配置;恢复默认后 `Shell Icons` 键删净不留空壳。
- 生效分两层:**注册表一写入,新进程立即按新图标合成**(资源管理器新开窗口、任何程序取图标都已是新状态);但**桌面**由常驻的 Explorer 进程绘制,它把「29=箭头」映射与合成结果缓存在进程内——F5、`ie4uinit`、`WM_SETTINGCHANGE`、`SHChangeNotify(ASSOCCHANGED)` 实测**全刷不动**(26H2 26300 实证;2026 年各家教程也一律要求重启资源管理器)。因此切换成功后工具会弹问句**代办重启资源管理器**:先快照你打开的文件夹 → 重启 → 原样重开,单窗口合并器自动并回标签页;选「否」则下次开机自然生效。

端到端测试:`tests/probe_arrow.py`(编译探针 exe 用 SHGetFileInfo 实拍 .lnk 合成图标,比对左下角箭头像素数;默认模式证伪 HKCU,管理员窗口加 `--hklm` 验证 HKLM 全链路)。

## ⚙️ 工作原理

调用 Win32 API `SetThreadExecutionState`,向系统挂一个**只属于当前进程**的唤醒请求:

```c
ES_CONTINUOUS | ES_SYSTEM_REQUIRED    // 阻止系统待机 / 休眠
             | ES_DISPLAY_REQUIRED    // (可选)同时保持屏幕常亮
```

- **进程级**:唤醒请求只属于本进程,进程退出(正常退出、被杀、直接关窗口、注销、重启),系统自动撤销请求,不留任何残留。
- **为什么还要临时改一处系统设置**:Win11 新型待机有一个「睡眠后休眠」固定计时器,**无视 `SetThreadExecutionState`**——即便唤醒请求挂着,屏幕熄灭数小时后系统仍会被强制休眠(实测:2026-10-02 凌晨,屏幕熄灭约 4 小时后系统进入睡眠,30 分钟后被 `Hibernate from Sleep - Fixed Timeout` 强制休眠到早晨)。因此防待机开启期间,程序会把「在此时间后休眠」的**交流(插电)侧**临时设为「从不」:原值经 PowrProf API 读取并备份在注册表 HKCU,关闭防待机或退出程序即恢复原值;若进程异常退出没来得及恢复,下次启动会检测到残留并自动恢复。**直流(电池)侧刻意不动**——合盖/电池场景的「睡后休眠」是保电闸门,合盖照睡、电池下睡后照常休眠。**退出即复原**:菜单退出、注销、关机都会自动恢复一切修改(恢复后配置键一并删净);进程被强杀的残留会在下次启动时自愈,也可随时手动执行 `KeepAwake.exe --restore-power` 立即恢复。开机自启是用户偏好,不随退出清除。
- **退出即恢复**:托盘版在退出时显式撤销请求;命令行版在 Ctrl+C / 到时后于 `finally` 中撤销。

**验证方法**:管理员终端运行 `powercfg /requests`,本进程会出现在 `SYSTEM` 请求列表里(开启屏幕常亮时还会出现在 `DISPLAY` 里);退出后条目随之消失。

## 📌 说明与限制

- **合盖行为不受本工具控制** —— 合盖睡不睡由电源计划的「合盖时」设置决定(默认睡眠)。需要合盖不睡:
  - Win11:设置 → 系统 → 电源 → 屏幕和睡眠 → 合盖时不执行任何操作;
  - Win10:在控制面板 → 硬件和声音 → 电源选项 →「选择电源按钮的功能」中设置。
- **普通用户权限即可** —— 需要管理员的只有 `powercfg /requests` 这条验证命令,以及「去除快捷方式小箭头」切换瞬间的一次 UAC(工具自我提权代办);常驻本身不需要。
- **系统要求**:Windows 10 / 11(托盘版依赖系统自带的 .NET Framework 4.x;命令行版仅支持 Windows,零依赖);**资源管理器单窗口合并**进一步要求 Win11 22H2+。
- 托盘版与命令行版**可同时使用**:两个进程各挂各的请求,互不干扰,都退出后才完全恢复。
- **开机自启**:右键菜单勾选「开机自启」即可——写当前用户注册表 Run 键(免管理员),exe 挪窝后下次启动会自动指向新位置;取消勾选即撤销。
